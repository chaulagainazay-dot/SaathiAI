## Executive Summary

This milestone addresses the **2 CRITICAL issues** identified in the Auth v1.1 audit:

1. **Bare SHA256 password storage** → Migrated to **PBKDF2-HMAC-SHA256** (600k iterations, salted)
2. **Orphaned Remember Me checkbox** → Wired to backend with per-session expiry enforcement

Additional hardening includes strict CORS whitelist, security headers middleware, session soft-delete revocation, passkey metadata, and a comprehensive production test suite.

## Changes by Area

### 1. Password Hashing (CRITICAL)

**Before:** `hashlib.sha256(password).hexdigest()` — unsalted, single-pass, trivial to brute-force.

**After:** `authsec.hash_password()` → `pbkdf2$sha256$600000$<salt>$<hash>`

| File | Change |
|------|--------|
| `saathi/authsec.py` | Already had correct PBKDF2 implementation |
| `saathi/server.py` | `_PASSWORD_HASH` init now reads `BAADAR_PASSWORD_HASH` env var; falls back to deriving from `BAADAR_PASSWORD` for backward compat |
| `saathi/server.py` | **Login** uses `authsec.verify_password(pw, stored)` — accepts both PBKDF2 and legacy SHA256 |
| `saathi/server.py` | **Change-password** stores `authsec.hash_password(new_pw)` |
| `saathi/server.py` | **Reset-password** stores `authsec.hash_password(new_pw)` |

**Backward compatibility:** `verify_password()` accepts both formats. Existing users can log in with their old password; on next password change, the hash is transparently upgraded to PBKDF2.

**Migration path for existing `.env`:**
```bash
# Old
BAADAR_PASSWORD=yourpassword

# New (recommended — hash generated by change-password or reset flow)
BAADAR_PASSWORD=yourpassword
BAADAR_PASSWORD_HASH=pbkdf2$sha256$600000$...
```

### 2. Session Store — Remember Me & Expiry (CRITICAL)

**Before:** `sessions.create()` ignored Remember Me. All sessions had 30-day cookie expiry only (client-side). No server-side expiry or revocation.

**After:** Per-session `remember_me`, `expires`, and `revoked` fields.

| File | Change |
|------|--------|
| `saathi/sessions.py` | `create()` accepts `remember_me: bool = True` |
| `saathi/sessions.py` | Stores `expires` = now + 30d (remember) or 24h (don't remember) |
| `saathi/sessions.py` | `validate()` rejects expired and revoked sessions |
| `saathi/sessions.py` | `revoke()` is **soft-delete** (sets `revoked=True`, preserves audit trail) |
| `saathi/sessions.py` | `revoke_all()` soft-deletes all except caller's session |
| `saathi/sessions.py` | `listing()` returns `expires` and `remember_me` |
| `saathi/server.py` | Login endpoint reads `remember_me` from body, passes to `sessions.create()` |
| `saathi/server.py` | Login endpoint sets cookie `max_age` based on `remember_me` |
| `saathi/server.py` | Passkey login verify reads `remember_me` from body |
| `saathi-os/lib/api.js` | `login(password, rememberMe = true)` passes `remember_me` to API |
| `saathi-os/lib/passkey.js` | `unlockPasskey(rememberMe = true)` passes `remember_me` to API |
| `saathi-os/app/unlock/page.jsx` | Remember Me checkbox state wired to API calls |

### 3. CORS — Strict Origin Whitelist

**Before:** `allow_origin_regex=".*"` with `allow_credentials=True` — **any website could make credentialed requests**.

**After:** Whitelist from `SAATHI_CORS_ORIGINS` env var. Defaults:
- `http://localhost:3000`
- `http://127.0.0.1:3000`
- `http://localhost:8765`

```bash
# Production
export SAATHI_CORS_ORIGINS="https://yourdomain.com,https://app.yourdomain.com"
```

## Known Limitations (Documented)

1. **Rate limiting is in-memory** — resets on server restart. Acceptable for single-owner.
2. **No email verification** — single-owner architecture; reset links are locally generated.
3. **Cross-origin cookies use `samesite="none"`** — required for localhost dev (different ports). Mitigated by custom `x-baadar-session` header.
4. **Passkey roaming authenticators** — YubiKey may not work with `resident_key=preferred`. Platform authenticators (Touch ID, Face ID, Windows Hello) are primary targets.
5. **CSP allows `unsafe-inline`/`unsafe-eval`** — required for Next.js dev builds. Production should tighten.
